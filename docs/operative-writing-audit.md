# 骨科手术记录“条件句/预案句”专项审核

日期：2026-10-13。适用范围：骨科所有**已经完成的手术记录**中的“手术经过”部分。

## 医学文书区分

- **术前讨论**可以写“若术中发现……拟……”，因为记录的是预案与风险应对。
- **手术记录**必须写实际所见、真实实施的步骤、实际使用的植入物、实际完成的检查结果；不能将“如果……则……”或“必要时……”描述为已经发生。
- **术后病程**可写未来计划，但已发生的拔管、查体、用药、影像或康复效果必须可核实。

## 本次实现

- 以最终病历编译前的只读检查为依据，扫描所有骨科手术记录中的“若、如需、必要时、可选择”等未落实措辞。
- `npm run audit:operative` 输出按类别汇总，不输出患者身份或源手术描述；`npm run audit:operative -- --detail` 提供病种与文书的非识别性元数据审核队列。
- 只对自动生成的“标准教学示例手术记录”作微调：移出一条显然属于备用方案的闭合复位失败应对句；对于确实无法确认是否实施的附加步骤，使用【待核实是否实施：……】保留核对入口。
- 对无法直接判断的其他“若/可选择/或”表述，只记入审查队列，不擅自写成已经完成的手术行为。
- 所有特殊病例、非骨科记录、术前谈话和未经授权的正文一律不做自动编辑。

## 临床人工修订标准

每篇手术记录逐一核实以下事项：手术名称与侧别、入路与体位、实际术中所见、真实解剖结构处理、具体复位/截骨/松解/修复步骤、植入物名称数量、术中透视与稳定性检查结果、引流及失血、并发症及实际术后医嘱。

面对缺失信息，必须使用可见待填写标记，并且**不能依据常规术式推定患者实际进行了某项操作**。不会直接把“必要时加用钢板”改成“加用钢板固定”。

## 审核验收

- GitHub 独立分支 + 草稿PR；`npm test`、`npm run build`、`npm run test:browser`。
- 逐记录对比，所有非适用正文、TKA的两套特殊病例完全不变；模板总数不变。
- Claude独立审核代码与医学生成逻辑；经过医生复核临床内容后再合并部署。

本轮目标是消除可确认的预案式写法，并生成剩余的人工审核清单，**不是声称全部手术记录已由临床医师确认**。
