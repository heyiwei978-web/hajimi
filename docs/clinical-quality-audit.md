# 哈基米工作站｜病历模板第一轮质量审核

审核日期：2026-10-12。范围：骨科模板库，先以 TKA 标准病历为样板；其他病种仅做数量保护。
**本阶段不修改、重写、删除任何原有医学正文，不部署生产环境。**

## 资料基线（上线核查所见）

- 4 个科室，总计 5,361 条模板记录，其中骨科 5,334 条。
- 骨科病种/项目 201 个；TKA 标准病历 28 章节、独立特殊病例 2 个。
- “记录数”不能直接等同于独立病种数；跨病种模板可重复。
- 上述数量作为**不得意外减少的下限**，如确有经批准的删除或归并，需单独评审并更新基线。

## 新增非破坏性审查功能

- npm run audit:clinical：按已发布源码的临床数据生成只读摘要，不改变任何病历。
- npm run audit:clinical -- --json /tmp/hajimi-audit.json：可选生成不含患者姓名、来源正文或检查结果的元数据报告。
- npm run audit:clinical:check：基本结构、数量下限、TKA 必需文书、两套特殊病例以及确定性的 POD 日期、引流管状态出现严重矛盾时退出失败。
- npm test：测试审查工具，包含“计划拔管”与“实际拔管”的区别；原有病历完整性测试继续执行。
- review/info 标记不等于临床审核完成；没有 error 也不能自动改为“已审核”。

## 后续迭代顺序

1. 运行自动测试及报告，先人工判断假阳性，不让程序直接修改医学正文。
2. 在 TKA 单病种内规范“待填写”与“已确认”状态，保留 28 章节和两套特殊病例时间线。
3. 小批量修正确认有误的字段拼接、引流状态、手术操作叙述，逐段进行医学审核。
4. 将流程推广到 THA、股骨转子间、胫骨平台与开放骨折，不进行全库盲目正则替换。
5. 每次对照正文差异与可靠证据，不以模板长度代替质量判断。

## 版本纪律

- GitHub 是唯一正式源码，重要修改在独立分支和 PR 里进行。
- 同一文件不让多个 AI 并行写入；Codex 实施，Claude 独立审查。
- 合并前执行 npm test、npm run build、npm run test:browser、npm run audit:clinical:check。
- 未经临床确认不覆盖医学事实，不删除特殊病例，不修改正式生产数据。
- 部署后核查搜索、预览、复制、目录跳转、手机端及加载情况，不用真实身份信息做第三方测试。
