# AI 生成限流独立整改建议（未实施）

本文件只提出后续方案。本次 AI 病历生成优化保留 `api/_note-limit.js`、`api/_security.js`、鉴权、WAF、环境变量和发布配置。

## 当前证据

`api/_note-limit.js` 按调用方 IP 摘要，在 Blob 的十分钟窗口中记录次数，窗口上限 20；计数通过读对象、增加、覆盖对象完成。Blob 读写异常按现有策略放行。

- 并发请求可能读到相同旧计数，覆盖后漏计；这不是原子计数。
- Blob 故障时额度保护失效，模型请求仍可能计费；现有管理员鉴权依然有效。
- IP 维度可能让共享出口的管理员共用额度；能否信任所取代理头需结合实际 Vercel/WAF 链路核实。
- 限流发生在 AI fetch 的 55 秒计时前；Blob 延迟会消耗函数 60 秒总执行预算。客户端超时只解决页面无限等待，不解决此预算竞争。

## 建议单独立项

1. 先在非生产环境用内存/受控存储和合成身份测试并发、窗口边界、存储超时及计费请求次数；记录无病情信息的状态码、计数一致性、耗时指标。
2. 负责人确定故障策略：保留 fail-open，或对计费接口在限流不可用时返回可重试错误；明确共享出口与账号维度的额度预期，不能在正文优化 PR 中擅自切换。
3. 评估原子计数后端或现有 WAF 的规则能力；仅在选型、成本、数据保留和迁移方案审阅后实施。存储只保留所需标识摘要、计数及过期时间，不保存病情和正文。
4. 给额度检查设置独立耗时上限，并在总函数预算内分配 AI 请求时间；保持统一错误提示及旧正文保留。
5. 独立 PR 提交并发测试、边界测试、故障模拟、隐私核对与回退方案。新方案通过后再由负责人决定合并和发布。

本方案不授权新增服务、改动额度、读取生产密钥、修改防火墙或生产部署。
