# 错误记录（2026-11-18）

线上页面或接口出错时，管理员能在 `/admin`「错误记录」里看到，不必等用户反馈。

## 记录什么

| 来源 | 怎么收集 | 记录的字段 |
| --- | --- | --- |
| 页面脚本报错 | `error-report.js` 监听 `error`、`unhandledrejection` | 报错文字、出错文件路径和行列号、页面路径 |
| 资源加载失败 | 同上（图片、脚本、样式） | 资源路径、页面路径 |
| 接口服务器错误 | 各接口默认导出用 `withMonitoring()` 包住 | 接口名、状态码或异常类型及简短说明 |

服务端额外记录浏览器标识和 Vercel 提供的国家代码。相同的报错（类型、文字、文件、行号都相同）合并为一条并累计次数，只保留最近 100 种。

## 不记录什么

页面正文、输入框内容、请求正文、Cookie、会话、本地存储，以及网址里的查询参数和 `#` 片段。报错文字里 6 位以上的连续数字替换为 `#`。浏览器端和服务端都会做这些清理。

## 上报脚本怎么进入页面

构建时由 `scripts/error-reporter.mjs` 把 `<script src="/error-report.js">` 注入每个发布页面 `<head>` 的最前面，紧跟 charset 声明，这样后续脚本的报错都能捕获。源 HTML 不改动，也避免在病历库 `index.html` 里加入与病历无关的脚本。每个页面最多上报 5 次，重复的报错只报一次。只上报本站脚本；跨域脚本只给出 "Script error."，不上报。

## 安全边界

`/api/login-log?feed=errors` 的 POST 是全站唯一不需要登录的写入接口，限制见 `FIREWALL.md`。查看（GET）和清空（DELETE）需要管理员登录。建议在 Vercel Firewall 中另外启用 `hajimi-client-error-limit` 规则，即每个 IP 每分钟 30 次。

## 处理流程

1. 打开 `/admin`，查看「错误记录」：按最近出现时间排序，显示次数、文件位置、页面和设备。
2. 修复后提 PR，上线后点「问题已处理，清空记录」，再观察是否复发。
