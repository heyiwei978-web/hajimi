# 完整病历框架与私有保存（2026-11-17）

执行：Codex。改动类型：代码、框架结构及新增文书写作提示。基线：main 257f8afc403742b57a883217860bbb10bb351758。
本功能按负责人本次需求开发；提交 PR 供审核，不代表已批准合并或上线。

## 使用方式

在现有 /note 页面录入一次虚构教学病情，选择现有接口提供的 DeepSeek 模型，再建立完整病历框架。
手术路径默认住院第 3 天手术、术后 14 天，每日病程分别生成，共 26 章；也可选择非手术路径和住院天数。
框架包含入院、首次病程、术前查房、主刀查房、小结、术前讨论、手术记录、术后首次病程、术后主刀查房、逐日病程、出院前查房及出院记录。
专科检查、会诊、阶段小结、交接班、转科、输血和抢救相关文书按需加入。知情同意书、医患沟通不纳入。
路径和天数修改后重新建立框架才生效；重建、换病例及覆盖单章正文均有清空/替换确认。

每章可单独录入补充要点或当天变化、AI 生成、编辑和人工核对；“生成未完成章节”仅处理空白章节。
失败、限流或手动停止会保留已完成结果，刷新不自动发起模型请求。沿用每 10 分钟 20 次的原接口限额，不增加并发或绕过限制。
共同病情改变时，已生成章节标记待重新核对。前一章模型输出不会作为后一章的病例事实。
非手术路径不把手术方式、麻醉及实际术中信息发送给生成接口。

“病历完成设置”要求每章有正文且完成核对，并确认整套保存；服务端重新校验章节身份、顺序、完整性、输入快照、字数和身份信息。
完成时按目录拼接原始正文，不调用 AI 重写，因此保留手工编辑及医学符号、签名横线。
已保存病历在同页显示、搜索、连续预览、整套复制，也可通过 /note?case=<UUID> 重新打开和继续编辑。

## 接口与数据

- 生成仍用 /api/note-generate，复用 NOTE_AI_API_KEY / NOTE_AI_BASE_URL / NOTE_AI_MODEL，保留原模型默认行为、补全模式、系统提示、输出清洗、超时和截断拒收。
- 新增经过同等管理员认证的 GET /api/note-generate，由服务端调用同一提供方的 /models；只展示返回的 DeepSeek 模型。可选模型由服务端再次核实，缓存 5 分钟；不接收客户端密钥或提供方地址。
- 未选择模型的旧请求仍直接使用原配置，不额外依赖模型发现。不自动替换原默认模型。
- 新章节沿用所选章节生成类型，并补充入院、术前讨论、会诊、出院等结构提示。新增提示词与真实模型输出需由负责人审核；技术测试不证明医学正确性。
- 保存 /api/note-cases 的读写均要求有效管理员会话；写操作保留同源、管理标识、JSON 和体积限制。响应 private, no-store。
- 仅使用既有固定凭据 Blob 客户端和 private 对象。按管理员标识摘要分区，每套独立存储并保存修改前快照，条件写防止多标签页覆盖。
- 私有目录只含名称、科室、诊断、章数及完成时间，正文不进入公开 CMS、病历模板身份账本或搜索索引。
- 正文写入成功而目录更新失败时返回明确提示和可用病历链接；重试保存可补齐目录，不把部分成功当成彻底失败。
- 未完成草稿仍只在 sessionStorage，未改成 localStorage。完成后正文和该套输入快照才由用户操作保存到私有服务端。
- 不变更医学源数据、身份账本、依赖、CSP、防火墙、发布配置、现有公开模板正文或知情同意书。

开发途中云端执行环境不可用，未在本地运行 Node / Playwright，也未访问生产后台、真实模型或生产 Blob。
