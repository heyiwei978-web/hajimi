## 在本站的应用

- 首页直接提供病历搜索和四个科室入口，用可操作的导航替代占据主要空间的装饰图。

## 心电图栏目框架 v2（2026-10-12）

心电图栏目的资料由多批文件叠加生成（基础数据、教材各批扩充、示意图、计算器和界面）。v2 保留原有写作方式，只调整加载和运行框架：

- **构建期编译**：`scripts/ecg-compiler.mjs` 在 `npm run build` 中执行所有资料文件，校验合并结果，并在 `dist/assets/` 输出一个带内容哈希的脚本。校验内容包括：词条 id 唯一、分类存在、示意图存在、相关词条和围手术期链接有效、参考文献使用 https、日期格式正确。任何一项不合格，构建即失败。`/assets/*` 设置一年 `immutable` 缓存；内容变化时文件名随之改变。
- **栏目内路由**：`/ecg` 下的链接由 `history.pushState` 在页面内切换，资料只下载和解析一次。每次切换先重置页眉、页脚和监听器，再把焦点移到新页面标题。返回时恢复原滚动位置。新标签页、下载链接和站外链接仍由浏览器处理。
- **全栏目搜索**（`ecg-search.js`）：参考 [MiniSearch](https://github.com/lucaong/minisearch) 和 [Fuse.js](https://github.com/krisk/Fuse) 的字段加权思路，按以下顺序排序：标题完全匹配、别名完全匹配、标题前缀、包含匹配、正文匹配。多个关键词须全部命中。英文短缩写（AF、PE）按整词匹配。代码为自写，不引入依赖，符合 `script-src 'self'`。高亮先转义再加 `<mark>`。搜索框按 [WAI-ARIA APG 组合框（列表自动完成）](https://w3c.github.io/wai-website/ARIA/apg/patterns/combobox/examples/combobox-autocomplete-list/)实现，支持 `/` 键、↑↓、回车和 Esc。
- **电子卡尺**（`ecg-calipers.js`）：思路来自 [EP Calipers](https://github.com/mannd/epcalipers)（Apache-2.0）：两条测量线，读取间期和对应心率。本站代码独立实现，未复制其源码。读数按示意图网格换算（1 小格 = 40 ms），只用于练习测量方法。
- **词条阅读**：同类词条之间有上一条 / 下一条导航，可打印本词条。打印样式会隐藏导航、按钮和固定页脚，自动展开围手术期层，并在外链后附上网址。

源码模式（未执行构建）下，`ecg.html` 仍逐个加载源文件，便于调试。`ecg.html` 中的脚本顺序须与 `ECG_SOURCES` 保持一致，否则构建会报错。

## 统一主导航（2026-11-22）

原先工作台各页（首页、临床、资料、学习、我的）用五项导航和手机底部标签栏，其余栏目用十项顶部导航、手机上横向滚动，换页时整套导航都会变。现在全站统一为五项：

- **五项**：工作台、临床、资料、学习、我的。病历模板、疾病分型、心电图、检验解读、临床路径、值班资料、临床工具、AI 病历生成属于「临床」，管理入口属于「我的」（注册表 `hub`）；打开这些栏目时高亮所属一项。各栏目入口在对应的工作台页面。
- **电脑宽度**：五项（图标 + 文字）在顶栏里，当前一项有底部指示条；工作台各页仍是左侧栏。病历模板库顶栏另有患者信息和登录，721–900px 只显示文字。
- **手机（≤720px）**：五项固定在屏幕底部、平分宽度，与工作台相同；顶栏只留标志（病历模板库另有患者信息和登录）。底部导航高度记在 `--site-tabbar-height`，正文底部留出同样空间，心电图词条页脚、合并慢性病按钮与抽屉、提示条都相应上移。手机上顶栏不做磨砂效果：`backdrop-filter` 会让顶栏成为底部导航的定位参照。
- **共用顶栏**：除工作台各页和病历模板库外，顶栏都由同一个模板生成（`site-header`），临床工具页不再有单独的顶栏结构。打印时隐藏顶栏和主导航。

## 全站搜索（2026-11-11）

首页搜索框原先只查病历模板，心电图、检验、工具各有各的搜索。现在新增 `/search` 页面，首页搜索框和首页顶栏的「搜索资料」都进入这里。

- **索引在构建时生成**：`scripts/site-search-build.mjs` 汇总各栏目已经公开的名称、缩写和别名——病历（每个病种/特殊病例一条，附章节名称）、疾病分型、心电图图谱与经典图、检验项目、临床路径、临床工具、栏目入口——输出 `dist/site-search-data.js`（约 80 KB）。**不收录病历正文、登录后才可见的资料和任何患者信息**，也不改写任何医学文字，只是指向已有页面。各栏目新增条目后，下次构建自动进入索引。

- 病历模板库、心电图、检验、工具各自的栏目内搜索保持原样。

## 青岚色系（2026-11-18）

V5 首页使用墨绿，其余栏目使用蓝色，全站主色不一致。本次统一为「青岚」色系，主色取在两者之间，只改屏幕显示。

- **主色阶**：50 `#eef7f8` · 100 `#d5ecef` · 200 `#a9d8de` · 400 `#3f9baa` · **600 `#11697a`（主色）** · 700 `#0c5564`（悬停） · 900 `#08333d`（浅底上的文字）。
- **中性灰（带青调）**：卡片 `#ffffff` · 背景 `#f5f8f8` · 线 `#dfe7e9` · 次要字 `#5d6f75` · 正文 `#2c3e44` · 标题 `#14252b`。
- **语义色不变**：成功绿、警示琥珀、危急红保持原值，只用于状态提示，不作装饰。
- **换色方法**：在 OKLCH 色彩空间把原蓝色、墨绿及偏蓝的灰色转到青岚色相，**保持明度不变**，所以文字与背景的对比度基本不变；与色阶相近的颜色直接对齐到色阶值。主色上的白字、白底上的主色链接对比度约 6.3:1。
- **未改动**：`@media print` 打印样式、`<script>` 内的颜色、心电图波形与示意图（`ecg-*.js`）、语义状态色。
- 变量名 `--ds-blue`、`--ws-blue` 为兼容保留，值已是青岚主色。

## 样式精简：删除无效规则（2026-11-18）

只删除不可能生效的样式，外观不变。

- **被覆盖的声明（493 条）**：同一选择器、同一属性，在后加载的样式里又写了一次（媒体条件相同或更宽，`!important` 不弱于前者），且在所有加载前者的页面中，后者都排在它之后，前一条永远不会生效。后一条的值若用到 `dvh`、`env()`、`clamp()`、带浏览器前缀的写法等可能不被支持的写法，就保留前一条作为兜底。
- **没有元素使用的规则（323 条）**：选择器里的类名或 id 在全部 HTML、JS、构建产物和内容数据中都找不到，连前缀拼接（如 `'ecg-risk-'+x`）也匹配不到。主要是旧首页（`official-*`、`portal-*`、`scene-*` 等）的遗留样式。`classification-home.css` 全部失效，已删除，并从病历库页面和发布白名单中移除。
- **结果**：规则 2,965 → 2,586，声明 9,896 → 8,295，样式总量约 318 KB → 276 KB；`styles.css` 73 KB → 48 KB。
- **核对**：构建后，用浏览器读取 21 个页面全部元素（含 `::before`/`::after`）的最终计算样式，在手机 390px、电脑 1280px 和打印三种情况下，与改动前逐项比对，完全一致。
- **注意**：管理员在后台写入的自定义 HTML 若用到上述旧类名，将不再有样式；目前未发现这种情况。

## 样式精简：公共样式合并为两层（2026-11-18）

原来每个页面先后叠加 `styles.css → ui-polish.css → accessibility.css → workspace-design.css → design-system.css` 五层公共样式。现在合并为两层，外观不变：

- **`styles.css`**：基础样式，末尾接原 `ui-polish.css`。
- **`theme.css`**：公共界面层，依次为原 `accessibility.css`、`workspace-design.css`、`design-system.css`，管理设计变量（`--ds-*`、`--ws-*`）。
- 本节之前提到的 `workspace-design.css`、`design-system.css`，现在都指 `theme.css` 中对应的部分。

各页面样式的加载顺序：

| 页面 | 顺序 |
| --- | --- |
| 病历库（`index.html`） | cms → styles → library-personal → case-workspace-preview → theme |
| 管理后台 | cms → admin → private-gallery → styles → theme |
| 疾病分型 | styles → classification → theme |
| 心电图 | styles → classification → theme → ecg |
| 值班 / 密码页 | styles → duty → theme |

| AI 病历 | styles → theme → note → note-case |

**新增页面样式**：要被公共界面层统一覆盖的，放在 `theme.css` 之前；要覆盖公共界面层的，放在 `theme.css` 之后。

**核对方法**：按原顺序和新顺序分别构建，读取 21 个页面全部元素的最终计算样式，在手机、电脑和打印三种情况下逐项比对，0 处不同。调整顺序后可能冲突的规则，即层叠优先级相同、选择器共用类名、取值不同的规则，逐条人工核对：只有心电图卡片悬停边框一处会受影响，已在 `ecg.css` 中补回，并用鼠标悬停实测与改前一致。

## 样式防叠加规则（2026-11-18）

为了不再出现"后面再写一条盖掉前面"的层层叠加，以下规则由 `test/css-layering.test.js` 在每个 PR 的 CI 中强制检查：

1. **没有写了也不生效的声明**：同一选择器、同一属性，在后面又写了一次，且后者的条件相同或更宽、`!important` 不弱于前者，并在所有页面都排在前者之后，就会报错，提示两条规则的位置。处理办法是修改原规则，删掉多余的那条。
2. **没有无人使用的规则**：选择器里的类名或 id 在全部 HTML、JS、脚本和内容数据中都找不到时报错。删除页面元素时要一并删除对应样式。
3. **样式文件清单固定**：根目录的样式文件必须与 `config/css-budget.json`、`scripts/public-assets.mjs` 一致，不能悄悄新增补丁式文件。
4. **`!important` 只减不增**：每个文件不得超过 `config/css-budget.json` 中记录的数量。
5. **直接写死的颜色只减不增**：定义变量（`--xxx: #…`）不计入；其他声明里的 `#…`、`rgb()`、`hsl()` 每个文件不得超过预算。新样式请引用 `--ds-*` 变量。

样式变少后，可以把预算改成新的、更小的值，之后就不能再涨回去。确需增加的，在 PR 中说明理由。

本地自查：`node scripts/css-guard.mjs`。

本次接入检查时，又发现 65 条被覆盖的声明和 80 条无人使用的规则。之前的分析把 `@media(` 这种不带空格的写法当成了未知规则而跳过了它们，这次一并删除。21 个页面在手机、电脑、打印下的计算样式与删除前逐项一致。
