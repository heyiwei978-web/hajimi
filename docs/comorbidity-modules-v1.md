# 骨科病历·合并慢性病独立补充模块（2026-10-21）

## 交互设计

进入骨科病种完整病历后，页面尾部显示“合并慢性病管理”独立板块，可单选或多选，按疾病展示五组书写参考段落（入院既往史、术前评估、内科会诊、术后病程、出院随访）。提供“仅复制已选慢性病补充”操作及清空选择。选择只保留在当前浏览器页面内，不写入服务端或长期储存。

首批八类：冠心病、高血压、脑梗死病史、糖尿病、心力衰竭、心房颤动、慢性肾脏病、慢阻肺。

**重要原则：不把慢性病文本直接拼入原来的示例病历。** 原网站大量标准病例明确写有“既往体健”“否认高血压、冠心病”等，并有固定虚构检验、诊断、用药和日期。简单向章末追加合并症将导致病历内部自相矛盾。因此原始章节显示、预览、单章复制和整套病历复制必须逐字维持；只有独立补充模块可复制，临床使用者须先在真实病历中核对、删除或重写与患者不符的基础病史及诊疗事实。

本设计不改变既有模板数目、患者示例、临床 JSON、CMS 数据结构、医学手术经过、两套 TKA 特殊病例、API、导航或安全配置。模块为额外的阅读与书写辅助信息，不构成真实患者“已完善某检查”“已实施某治疗”或治疗许可的证明。

## 内容与校验要求

- 冠心病：确认近期胸痛和心衰征象、既往心梗/PCI与抗血小板治疗；心脏超声申请需有可能影响决策的症状或体征依据，稳定无症状者不因冠心病史例行重复检查。
- 高血压：实际血压趋势、降压方案、靶器官损害和术中血流动力学风险。
- 脑梗死病史：卒中时间、神经功能基线、抗栓药物；急诊髋部骨折与择期术式区分考虑。
- 糖尿病：HbA1c及围手术期血糖、胰岛素和SGLT2抑制剂、低血糖风险，结合老年和衰弱状态调整目标。
- 心衰、房颤、慢性肾病和慢阻肺：按病情检查/会诊，重点管理液体状态、心率/抗凝、肾功能剂量和呼吸并发症。
- 所有【待核实】指标、医嘱及患者症状都不得直接认定为实际事实。

## 主要依据

2. American Diabetes Association, **Standards of Care in Diabetes—2026**, section 16：https://doi.org/10.2337/dc26-S016

## 验收与上线边界

- 未选择时只显示独立入口；已选择时显示五组资料并可独立复制。
- 选择、清空、切换病种均不能修改原始文本、手术记录、出院章节、特殊病例或“复制完整病历”的内容。
- 手机与电脑浏览器测试、整库医学正文回归、公开资源白名单验证均须通过。
- 仓库 PR 审查、生产环境安全核查及域名发布是独立步骤；自动部署已对本分支关闭，严禁绕过历史 G4 和 A7 记录或直接借用未经核实的 Preview 环境凭据。

## 2026-11-01 交互更新：选项置顶、病历旁补充内容框

只改展示方式，八类慢性病的补充文字逐字不变，原病历正文、单章复制、整套复制和打印均不受影响。

- 选项：骨科完整病历页面在病历目录上方显示“合并慢性病（可多选）”八个选项和“清空选择”。
- 电脑（≥1280px）：勾选后病历右侧出现第三栏“慢性病补充内容”，吸顶跟随滚动；页面自动加宽，正文宽度不被挤压。
- 手机及较窄屏幕：勾选后右下角出现“慢性病补充（数量）”按钮，点开为底部弹出面板，可“收起”或按 Esc 关闭。
- 随章节切换：阅读入院章节显示“入院记录与既往史”；术前及术中章节显示“术前评估”和“专科会诊”；术后章节显示“术后病程与监测”；标题含“出院”的章节显示“出院随访”。也可手动点“入院/术前/术后/出院/全部”，点“跟随阅读章节”恢复自动切换。
- 复制：每个内容框可单独复制该段文字；“复制已选全部补充”与原来的独立补充模块格式相同。
- 打印时选项、补充面板和按钮均隐藏。

## 2026-11-01 第二次更新：新增入院三天检查—会诊流程的填空模板

站点负责人要求增加：入院第1天主治医师查房（因基础病完善检查）、第2天检查结果回报及请内科/麻醉科会诊、会诊记录、第3天根据会诊意见调整。

- 四个部分是**通用填空模板**，由界面代码生成，只自动填入病名，其余为【】空白，不含针对具体疾病的医学判断；原八类慢性病补充文字逐字不变（测试校验其哈希）。负责人选择先用通用模板，以后可由内容方按病种撰写具体内容、经医学审核后替换。
- 侧栏阶段按钮：入院、第1天查房、第2天会诊申请、会诊记录、第3天调整、术前、术后、出院、全部。
- 自动对应章节（按阅读顺序）：入院记录/首次病程→入院；主治医师首次查房（含合并的“入院查房记录”）→第1天；主任医师首次查房、选择治疗方案沟通、术前主刀查房→第2天；多学科术前讨论/会诊→会诊记录；知情同意、麻醉术前访视→第3天；术前小结、手术→术前；术后→术后；标题含“出院”→出院。
- “复制已选全部补充”按住院时间顺序包含全部九个部分。

## 2026-11-01 第四次更新：开发者模式可编辑

- 登录开发者模式（站点现有管理员登录）后，补充内容框（合并慢性病各阶段、特殊检查各项）每段旁出现“编辑”按钮；可就地修改并保存，或“恢复默认”。访客只看到保存后的内容，没有编辑按钮。
- 修改保存在现有 CMS 资料（私有 Blob `cms/content.json`）的可选字段 `supplementOverrides`：键为 `c:<慢性病id>:<字段>` 或 `x:<检查id>:<字段>`，值为 `{body, updatedAt}`。沿用 `PUT /api/content` 的管理员会话、同源与管理请求标识校验、ETag 并发保护和保存前自动备份；服务端校验键格式、正文非空且不超过 8000 字、最多 500 条，未知字段丢弃。
- 只替换补充内容的显示与复制文字；原病历正文、身份账本、整套复制与打印不受影响。修改后的内容由负责人自行负责，不经过病历修订授权流程。

## 2026-11-02 第五次更新：特殊检查只显示申请理由；正文保存后即时刷新

- 特殊检查补充框只显示「申请理由（可改用）」一栏，不再显示「需写明」「注意」两栏，复制内容同步只含申请理由。`special-exams.js` 中的原始资料（`record`、`caution` 字段）未改动，只是不展示。
- 开发者模式下「编辑正文」保存或「恢复默认」后，页面上的整套病历章节立即显示新正文，不需要刷新页面；阅读位置、已勾选的补充内容和预览弹窗保持不变。
