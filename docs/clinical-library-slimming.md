## 清单与稳定身份

- `content/clinical-library/baseline.json`：基准提交、生成链文件哈希、既有质控结果、完整病例及成员列表。
- `content/clinical-library/records.jsonl`：逐文书的科室、项目组、病例类型、所属病例、阶段、类型、原名、原数字 ID、稳定 ID、原正文/默认生成正文哈希、最终显示正文哈希、记录全字段哈希、引入脚本、特殊病例标记、CMS 风险与保留建议。
- `content/clinical-library/publication.json`：版本化归档决定；当前为空。

`clinical-v1-rNNNNNN` 的编号来自已提交的身份账本，而不是下次构建的数组位置。编译器按身份匹配账本并保留原数字 ID；源码对象重新排列不会重编号。源码正文、记录字段、数量或身份不匹配时停止构建，不能静默重建账本。该限制意味着以后授权修改医学内容时，也必须显式审核更新对应账本，不应重新执行初始化来覆盖原身份。

清单的 `cmsOverrideExists` 和 `cmsCaseExists` 为 `null`，表示没有读取核实生产数据，不表示不存在。所有记录都有生产 CMS 未核验风险标记。

## 归档门禁

当前 203 个普通病例均为其项目组内唯一已确立标准病例，全部建议保留。两个特殊病例以及四个独立通用场景不归档；不同疾病、独立术式和治疗路径不自动合并。

发布规划器只接受整套普通病例的显式归档决定，要求同项目组的保留替代病例、原因和审核人。特殊病例、跨术式替代、替代病例也被归档、未核验 CMS 和歧义名称均被阻止。普通 `npm run build` 不提供生产 CMS 审核凭据，任何实际归档决定都会停止构建。没有环境变量绕过开关。

真正启用归档前仍须完成生产映射审核、归档病例历史锚点重定向及受控重新发布验证。本 Draft 不是实际归档的发布授权。

## 不部署与回滚

`vercel.json` 仅为 `chore/clinical-library-slimming` 分支设置 `git.deploymentEnabled: false`，防止 Git 推送触发 Vercel 自动预览；生产分支规则保持原样。本任务不运行任何部署命令，不合并 PR。

当前回滚只需撤回此 PR 的构建、加载器和辅助文件改动，再执行原构建。所有医学源文件、生成顺序和生产 Blob 保持原状，没有需要恢复的患者资料或存储迁移。未来实际归档也必须保留源文件与基准提交，并通过移除归档决定重新发布，而不是恢复一份旧 Blob 覆盖新资料。
