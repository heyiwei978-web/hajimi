# 私人图片库

管理员从 `/admin` 登录后，在“私人图片库”保存和查看图片。支持多张 JPG、PNG、WebP、分类（DR／外伤／术中／其他）、标题与说明搜索、放大预览。没有公开发布按钮。

浏览器沿用 `image-upload.js`：将教学副本重新编码为 JPEG，最长边1800像素、压缩后每张不超过3MB。图片内可识别文字仍需上传前遮盖。这里不接收 DICOM 原始检查文件，也不保存到浏览器 localStorage。当前每库最多500张。

## 访问与数据边界

- 沿用现有唯一管理员账户、签名会话、同源写入校验及管理请求标识。
- `GET/POST /api/private-gallery` 和 `GET /api/private-image` 在任何存储访问前验证管理员；未登录、过期、伪造或非当前管理员会话返回401。
- 图片元数据为私有 Blob `private-gallery/index.json`；图片为 `private-gallery/images/<uuid>.<ext>`，修改前备份为 `private-gallery/history/`。不返回存储服务的原始 URL。
- 图片接口只读取索引内的严格合法路径和 JPEG／PNG／WebP MIME，强制 `private, no-store` 与 `nosniff`。既有公开图片接口拒绝私人图片路径。
- 私人索引与 `cms/content.json` 完全分开，公开案例的保存、发布、备份与恢复不会包含或覆盖私人图片库。
- 保存使用 ETag 条件更新，写索引前必须备份，防止并发覆盖。索引保存失败时可能留下私有、未索引文件；图片接口拒绝读取这些文件。本次未提供删除或存储清理功能。
- 批量上传逐张确认，失败后保留剩余文件并要求刷新核对后继续，避免自动重试不确定的写入。
- 退出登录、页面离开、前台会话检查发现失效时清除预览及对象 URL；可见页面每60秒检查会话，回到页面时也检查。已看到或截取的图片无法远程收回。

这是网站访问权限功能；医院资料使用、患者授权和图片画面脱敏仍需独立处理。既有公开案例不会自动迁移。

## 验证

仅使用随机会话密钥、虚构凭据、合成图片和内存存储；未登录生产管理员，未上传患者图片，未访问生产私有图片库。

- 原有201项单元测试通过；源码副本最初缺少 Git 上下文导致其中1项 CLI 测试失败，补齐本地 Git 上下文后单独复测通过。
- 新增6项图库测试覆盖：匿名／过期／伪造／其他用户拦截，CSRF、格式及大小限制，私有保存读取，公开接口隔离，路径和 MIME 限制，并发版本冲突，备份／存储失败与未索引图片拒绝。
- 权限、Blob 凭据、内容存储和图库相关57项测试通过。
- `npm run build` 通过；临床源码、身份台账及正文未修改。
- `e2e/private-gallery.test.cjs` 在本地 Chromium、375与1440像素视口验证真实页面→真实处理器→内存存储→图片预览流程，覆盖匿名隐藏、批量保存、分类搜索、放大、退出后直链401、重新登录读取、会话失效清除，以及批次中断后只继续剩余图片。不是实机或生产 Blob 验收。

常规执行：`npm run build`、`node --test test/private-gallery.test.js test/security.test.js test/content-store.test.js test/blob-auth.test.js`、`node --test e2e/private-gallery.test.cjs`。浏览器可通过既有 `CHROMIUM_EXECUTABLE_PATH` 指定；受限测试运行器可额外设置 `CHROMIUM_SINGLE_PROCESS=1`。
