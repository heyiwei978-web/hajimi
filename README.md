# hajimi

私有临床工作台网站源码。

## 页面结构

- `/`：总首页
- `/bl`：病历模板科室入口
- `/bl/guke`：骨科
- `/bl/puwai`：普外科
- `/bl/shennei`：肾内科
- `/bl/fuke`：妇科
- `/tools`：临床工具
- `/duty`：值班核对、待办及交班摘要
- `/admin`：资料集中管理、备份与历史恢复
- `/api/*`：登录、内容、图片与上传接口

## 疾病分型栏目

- `/classification` 与病历、路径保持同级，先展示科室；`/classification/guke` 为骨科专区，其他科室保留各自目录。
- 现有17个骨科病种、135条分型/亚型保留原有定义、影像鉴别、文献图源及病种总述。`classification-treatment.js` 按原始分型名称对应保守条件、手术判断和可选方案。
- 逐型方案是结合指南及AO技术参考的临床整理；页面分别列明资料层级、适用范围、随访和核查日期，不能视为每型都有独立指南推荐。
- 每个病种提供分型定位、可展开的对照表与可刷新分享的 `#type-N` 链接；目录搜索涵盖具体亚型及形态词，兼容Unicode/ASCII罗马数字。
- 部分官方细码仍按组汇总，逐型授权影像与独立推荐等级尚未完整补齐；现有图源外链和审核标记继续保留。

## 部署

生产平台：Vercel  
生产域名：`wdyxzl.icu`

此仓库作为 hajimi 网站的唯一源码。后续修改先完成本地验证并提交 GitHub；Git 合并与生产发布分别审阅和授权。

敏感配置只保存在 Vercel Environment Variables，不提交到仓库。

GitHub 已连接 Vercel，采用**合并即上线**：PR 合并到 `main` 后，Vercel 自动构建并发布到生产。合并前须确认 CI 全部通过、预览部署检查无误；`vercel.json` 仍禁用若干历史分支的自动部署。详见[发布与核验流程](docs/deployment-workflow.md)。


## 开发与检查

- `npm run build`：从 `index.html` 的首页区块生成轻量的 `home.html`，并生成 `dist/` 发布目录。发布目录的 `index.html` 是轻量首页，`library.html` 保留完整病历，避免静态首页覆盖路由规则。Vercel 部署时自动运行。
- `npm test`：验证安全边界、病历生成链、首页构建与搜索过滤。
- `npx playwright install chromium` 后执行 `npm run test:browser`：验证手机和电脑卡片边框、中文搜索、分页、弹窗、键盘操作和打印布局。可通过 `CHROMIUM_EXECUTABLE_PATH` 使用本机 Chromium。GitHub Actions 自动运行这两类检查。
- 病历数据仍通过 `/bl` 加载；首页样式与入口内容继续维护在 `index.html`，不要直接修改生成的 `home.html`。
- 本地预览应服务 `dist/`，根据 `vercel.json` 路由到对应页面；API 仍位于仓库根目录的 `api/`。
- 修改 HTML 后请先运行构建，再检查电脑和手机端的组件边界、搜索、病历预览及临床工具。

## 管理资料保护

- 管理页面的“备份与修改历史”支持下载当前资料、下载历史备份和恢复最近 50 个版本。
- 每次保存或恢复前，服务器先创建私有备份；备份或读取失败时停止修改。
- 保存需要当前资料版本，并通过 Blob 条件写入防止多个页面相互覆盖。出现版本冲突时，请复制保留编辑中的草稿后刷新。
- 修改历史和恢复接口仅向已登录管理员开放，公开浏览不会返回未发布案例。
- 备份包含模板自定义正文和案例资料；图片沿用原有私有存储文件，恢复不会删除图片。

## 病历按需加载

- 原始病历及质量修订脚本继续按 `index.html` 中的顺序维护。构建时运行完整生成与检查链，生成按科室划分的目录和按病种划分的正文文件。
- 发布页面仅加载当前科室目录，进入病种或点击预览/复制时才读取相应正文。跨科室搜索按需补充其他科室目录。
- 发布资源使用内容摘要命名，资料更新后自动切换新文件；加载失败支持重试，通用场景继续在浏览器内应用患者信息。
- 自动检查逐份比较全部 5,159 条记录的字段、正文与特殊病例顺序，确保数据拆分不改变病历。

## 本机常用入口

- 病种完整病历页支持收藏/取消收藏，病历库首页显示最多 50 个收藏和最近 12 个病种入口。
- 仅在 `localStorage` 保存科室和病种标识，不保存患者信息、病历正文或病例图片；无需登录，同一浏览器的标签页会同步。
- 浏览器禁止存储时，当前页面仍可使用收藏；页面会明确提示无法持久保存。

## 病历搜索与阅读

- 搜索结果仍按病种合并，每张卡片显示最多三份实际匹配的文书名称、阶段及类型，并高亮关键词；搜索只使用目录信息，不提前下载正文。
- 完整病例目录和预览提供 18、20、22 像素三档字号，目录、正文和预览同步调整。仅字号偏好保存在 `localStorage`，同一浏览器的标签页同步；存储不可用时显示“仅本页生效”。
- 当前文书在目录中同时用颜色、边框和文字标记。字号与高亮只改变显示，不改变病历正文、复制结果或打印字号。
- 界面按需使用 Tabler SVG 图标，不加载整套框架；授权信息见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 值班工作台

- `/duty` 独立轻量页面提供接班、值班中和交班前的工作核对清单，具体流程仍以医院制度为准。
- 待办支持可选计划时间、完成/删除与到时提示；交班摘要可复制、下载为文本或打印。
- 草稿仅在当前标签页的 `sessionStorage` 保存，不上传、不写入长期本机存储，支持清空；无法保存或复制时会提示。
- 常用资料入口连接现有病历、临床路径与工具；`/tools?tool=news2` 等链接可直接打开对应工具，公式保持不变。

## 后台集中管理

- 管理后台集中列出模板自定义正文、全部案例（包括未发布草稿）及当前图片引用，支持名称/所属模板搜索、展示状态筛选和每次 50 项分页。
- 支持编辑正文、恢复系统默认正文、编辑/发布/删除案例、添加图片和移除图片引用，均沿用版本检查和自动备份。
- 编辑中的草稿只留在页面内，可下载 JSON 留存；保存失败保留表单，版本冲突时需先下载草稿、刷新核对，避免覆盖其他修改。
- 图片列表按存储路径合并相同引用；移除引用或删除案例不会删除图片文件，历史恢复仍可使用。列表只展示当前资料中引用的图片，不列出未引用的存储文件。
- 病历库与后台共享图片处理流程，缩放至最长边 1800 像素并重新编码为 JPEG；上传前仍须手动去除可识别的画面文字。
- 资料读取失败时禁用管理操作，退出登录会清空管理列表、搜索条件和编辑草稿。
- 病历页退出失败会明确提示；退出成功后只保留公开案例，并清空案例编辑草稿。
